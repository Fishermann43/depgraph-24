# Визуализация графа зависимостей Cargo (вариант 24)

## 1. Общее описание

Учебный проект по конфигурационному управлению.
Инструмент командной строки: строит граф зависимостей Rust-пакета
(Cargo) и показывает его в удобном виде. Готовые менеджеры пакетов
и сторонние библиотеки для получения зависимостей не используются —
только стандартная библиотека Python. Работа выполнена поэтапно,
каждому этапу соответствует ветка `stage-N`.

## 2. Функции и настройки

Настройки задаются только опциями командной строки:

| Опция | Назначение |
| --- | --- |
| `--package` | имя анализируемого пакета (обязательно) |
| `--repo` | URL репозитория или путь к файлу тестового репозитория |
| `--test-mode` | режим тестового репозитория: `on`/`off` (по умолчанию `off`) |
| `--image` | имя сгенерированного файла с изображением графа (обязательно) |
| `--ascii-tree` | вывод зависимостей в формате ASCII-дерева: `on`/`off` |
| `--max-depth` | максимальная глубина анализа, `0` — без предела |

Этап 1: программа выводит полученные настройки в формате ключ-значение.
Ошибки всех параметров обрабатываются и показываются пользователю:
отсутствие значения, пустое имя пакета, плохой адрес репозитория,
пустое имя файла, неверный флаг, неверная глубина.

Этап 2: программа обращается к API crates.io (карточка пакета,
свежая не отозванная версия, список её зависимостей) и выводит
прямые зависимости пакета — учитываются обычные, не опциональные.

Этап 3: в режиме `--test-mode on` граф читается из тестового файла
(строки вида `A: B C`, пакеты — большие латинские буквы) и строится
поиском в ширину без рекурсии (явная очередь). Учитывается
максимальная глубина (`--max-depth`, `0` — без предела), циклы
находятся и выводятся, программа не зацикливается.

Этап 4: опция `--ascii-tree on` рисует зависимости текстовым деревом
(`+--`, `` `-- ``, `|`). Повторные вершины помечаются `(повтор)`,
поэтому циклы дерево не зацикливают. Пример вывода для трёх пакетов
(цепочка, ветвление, цикл) приведён ниже в разделе «Примеры
использования». Сравнение со штатным инструментом (`cargo tree`):
порядок и состав уровней совпадают; возможные расхождения —
в опциональных и dev-зависимостях, которые инструмент по заданию
не учитывает, и в сортировке независимых пакетов — объясняются
разными правилами упорядочивания и на корректность не влияют.

Этап 5: в тестовом режиме программа всегда сохраняет изображение
графа в файл `--image` (формат SVG: прямоугольники-вершины
по слоям поиска в ширину, стрелки-рёбра). Пример — файл
`graph.svg`, полученный из тестового репозитория выше.

## 3. Сборка и запуск тестов

Сборка не требуется, нужен только Python 3. Тесты:

```sh
./run.sh
```

или вручную:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -t . -v
```

## 4. Примеры использования

Вывод настроек:

```sh
PYTHONPATH=src python3 -m depgraph --package serde \
  --repo https://crates.io --image graph.png --max-depth 2
```

Ожидаемый вывод:

```text
package=serde
repo=https://crates.io
test_mode=False
image=graph.png
ascii_tree=False
max_depth=2
```

Пример обработки ошибок:

```sh
PYTHONPATH=src python3 -m depgraph --package " " \
  --repo https://crates.io --image graph.png
```

```text
ошибка: имя пакета не должно быть пустым
```

Визуализация зависимостей трёх пакетов в виде ASCII-дерева:

```sh
PYTHONPATH=src python3 -m depgraph --package A \
  --repo tests/testdata/branch.txt --test-mode on \
  --image graph.png --ascii-tree on
```

```text
ascii tree:
A
+-- B
|   `-- D
`-- C
    `-- D (повтор)
```
